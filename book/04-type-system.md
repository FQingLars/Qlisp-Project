# Глава 4. Система типов

## 4.1 Постепенная типизация

QLISP — язык с **постепенной типизацией** (gradual typing): аннотации необязательны, но там, где они есть, компилятор их проверяет и использует для оптимизации.

```lisp
;; Без типов — полностью динамический код
(defun add (a b) (+ a b))

;; С типами — как аннотации Python
(defun add (a: Int b: Int) -> Int (+ a b))

(defun square (x: Float) -> Float (* x x))

(defun mixed (a: Int) -> Int a)
```

> 🐍 **Python-аналогия.** Прямое соответствие с type hints:
> ```python
> def add(a: int, b: int) -> int: return a + b
> def square(x: float) -> float: return x * x
> ```

Доступные аннотации: `Int`, `Float` и типы значений рантайма (`String`, `List`, `Tensor` и т.д.).

## 4.2 Форма `the`

`(the T expr)` — утверждение «это выражение имеет тип T»:

```lisp
(the Float 3.14)        ; float, как 3.14
(the Int 42)            ; int
(the Float (mixed 10))  ; int-значение под float-типом
```

> 🐍 Это `typing.cast(T, expr)` — подсказка компилятору/проверяющему без изменения значения.

## 4.3 Что дают аннотации

1. **Ранние ошибки.** Несовпадение типов ловится на этапе компиляции, а не падением в рантайме.
2. **Оптимизации.** Компилятор знает, что `x: Float` — это double, и генерирует соответствующие машинные инструкции без проверки тегов.
3. **Документация.** Сигнатура видна в LSP-подсказках (`qlisp-lsp` показывает параметры и типы).

## 4.4 Линейные типы тензоров

Для `Tensor` действуют **линейные правила использования**: тензор — это не «ссылка на буфер», а значение с одним владельцем. Многие операции **потребляют** вход:

| Операция | Что происходит с аргументами |
|---|---|
| `(MATMUL! x w)` | `x` потреблён, `w` не тронут, результат — новый тензор |
| `(clone x)` | `x` не тронут, возвращается копия |
| `(setq w v)` | обновление `w` на месте |
| `(defvar w v)` | `v` клонируется в долгоживущую память |

Это не borrow-checker (никаких lifetime-аннотаций) и не счётчик ссылок — просто одно правило: **у значения один владелец; нужно оставить себе копию — явно вызывайте `clone`**.

> 🐍 **Python-аналогия.** В NumPy/PyTorch почти всё — shared views: `b = a[0]` даёт представление над тем же буфером, и `b` неожиданно меняет `a`. В QLISP views нет: `reshape` и `transpose` делают глубокую копию. Это медленнее на копирование, но исключает целый класс багов aliasing'а и позволяет арена-аллокатору (гл. 5) мгновенно освобождать память.

## 4.5 Интроспекция типов

```lisp
(type-of 3)         ; → int
(type-of 3.5)       ; → float
(type-of "s")       ; → string
(type-of '(1 2))    ; → cons
(type-of (tensor ((1.0))))  ; → tensor
(type-of car)       ; → primitive / closure
```

> 🐍 `type-of` ≈ `type(x).__name__`.

## 4.6 Проверка типов вручную

Модуль `ERRORS` предоставляет `type-check` и утверждения:

```lisp
(import ERRORS)
(assert-type 3.14 'float)       ; бросает ошибку, если не float
(type-check 3 'int)             ; → t
(type-check "s" 'tensor)        ; → nil
```

> 🐍 `assert-type` ≈ `assert isinstance(x, float)`.

## 4.7 Рекомендации

- Аннотируйте **границы модулей** (экспортируемые функции) — внутри можно оставить динамикой.
- В ML-коде главные типы — `Float` и `Tensor`; аннотируйте функции forward-прохода.
- Не боритесь с линейностью тензоров: проектируйте поток данных «один владелец, явный clone» — это и есть стиль QLISP.
