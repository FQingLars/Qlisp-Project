# Глава 14. Символьное программирование

QLISP — не просто «Лисп для тензоров»: в ядро встроен **символьный движок** — паттерн-матчинг, унификация, property lists, rule engine и нейросимвольная маршрутизация. Это делает QLISP подходящим для expert systems, knowledge graphs и нейросимвольного AI.

## 14.1 Pattern matching: `match`

```lisp
(match value
  (pattern-1 результат-1)
  (pattern-2 результат-2)
  (_ дефолт))
```

Паттерны:

| Паттерн | Что сопоставляет |
|---|---|
| `_` | что угодно (wildcard) |
| `(? x)` | что угодно, связывает переменную `x` |
| `42`, `"hi"`, `'sym` | литерал |
| `(list (? a) (? b))` | список из двух элементов |
| `(cons (? h) (? t))` | cons-ячейка: голова + хвост |
| `(or p1 p2)` | любой из паттернов |
| guard-условия | дополнительные проверки |

Примеры:

```lisp
(match 42
  (42 "сорок два")
  (_ "другое"))                       ;; → "сорок два"

(match (list 1 2 3)
  ((list (? a) (? b) (? c)) (+ a b c))
  (_ 0))                              ;; → 6

(match (cons 1 2)
  ((cons (? a) (? b)) (+ a b)))       ;; → 3
```

> 🐍 **Python-аналогия.** Это `match/case` из Python 3.10+, но с настоящими биндингами переменных по структуре:
> ```python
> match value:
>     case [a, b, c]: return a + b + c
>     case _: return 0
> ```

## 14.2 Унификация: `unify` и `subst`

Унификация — сердце Prolog: найти подстановку переменных, при которой два выражения совпадут (с проверкой occurs check):

```lisp
(unify '(? x) '(foo bar))          ;; → подстановка: x = (foo bar)
(unify '(f (? x) b) '(f a b))      ;; → x = a
(subst '((? x) . replacement) expression)   ;; применить подстановку
```

> 🐍 В Python унификацию делают библиотеки типа `unification`/`kanren` — в QLISP она встроена.

## 14.3 Property lists: свойства символов

Каждый символ может нести словарь свойств (глобально, в immortal-памяти):

```lisp
(put 'cat 'legs 4)
(get 'cat 'legs)        ;; → 4
(symbol-plist 'cat)     ;; все свойства
(remprop 'cat 'legs)
```

> 🐍 Это «атрибуты у enum'ов»: `class Animal(Enum): CAT = ...` + `CAT.legs = 4`. Классика Common Lisp, удобна для метаданных.

## 14.4 Rule engine: факты и правила

Forward-chaining движок: факты — S-выражения, правила выводят новые факты.

```lisp
;; факты (цитируются — это данные)
(assert-fact (warm-blooded? cat))
(assert-fact (has-fur? cat))
(assert-fact (live-birth? cat))

;; правило: все тёплые+шерсть+живорождение — млекопитающие
(defrule mammal ((? x))
  (when (warm-blooded? (? x))
        (has-fur? (? x))
        (live-birth? (? x)))
  (assert (mammal? (? x))))

(run-rules)                    ;; прогнать вывод

(query (mammal? cat))          ;; → t: cat — млекопитающее
(query (mammal? (? who)))      ;; → все решения переменной who
(retract-fact (has-fur? cat))  ;; убрать факт
```

Структура правила: `(defrule имя (переменные) (when условия...) (assert следствия...))`. Правила могут **цепляться** (выведенный факт запускает следующие правила). Бэктрекинг реализован через механизм `amb` (ниже).

> 🐍 Прямого аналога в Python нет — это territory pyDatalog/CLIPS/Prolog. Но обратите внимание: факты и правила — обычные S-выражения, их можно строить макросами (гл. 12).

## 14.5 Недетерминизм: `amb-let` и `amb-collect`

Логическое программирование через «amb» (ambiguous choice) с бэктрекингом:

```lisp
(amb-collect
  (amb-let (x '(1 2 3))
    (amb-let (y '(1 2 3))
      (if (> (* x y) 4) (list x y) nil))))
;; все пары (x y), где x*y > 4
```

> 🐍 Аналог — `itertools.product` + фильтр: `[(x, y) for x in xs for y in ys if x*y > 4]`.

## 14.6 Neuro-symbolic: `NS-IF` и `NS-GRAD!`

Уникальная конструкция QLISP: **нейросимвольное дерево**. Символьная развилка `NS-IF` маршрутизирует данные в одну из нейросетевых ветвей, и автоградиент (гл. 7) корректно распределяет ошибку:

```lisp
(defvar logits (matmul! x router-w))    ;; логиты решения

(defvar pred (ns-if logits
  (("dog") (matmul! x dog-net))         ;; ветка «собака»
  (("cat") (matmul! x cat-net))))       ;; ветка «кошка»

(defvar loss (mse! pred y-true))
(ns-grad! loss 'cat)                    ;; backward с учётом маршрута
```

«Детектор вины» (guilt detector) решает, кто виноват в ошибке:

- **Маршрут верный** → градиент течёт в нейросеть листа (обычный backward).
- **Развилка ошиблась** → градиент получает **роутер** (через straight-through estimator по логитам), а неверно выбранная ветка **блокируется** (не штрафуется).

> 🐍 Это гибрид `nn.Module` с `torch.gather`-маршрутизацией и hard attention: представьте дерево if-ов, где каждая развилка — обучаемая нейросеть, и весь граф дифференцируем. В PyTorch такого из коробки нет — здесь это две формы языка.

## 14.7 Когда символьный слой полезен

- Expert systems поверх ML-моделей: правила фильтруют/маршрутизируют предсказания.
- Knowledge representation: факты + унификация + запросы без внешнего Prolog.
- Обучаемые решающие деревья с нейросетями в листьях — `NS-IF` ровно про это.

Символьный слой живёт на S-выражениях в immortal-памяти (гомоиконность), нейронный — компилируется через HLO (гл. 10). QLISP сознательно разделяет эти миры: интроспекция правил не мешает нативной скорости тензоров.
